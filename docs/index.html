01 / Publishing

The same Cargo and npm.

Point your clients at your server. Publish and install with the commands you already know, including scoped npm packages and Cargo registry dependencies.

02 / Storage

Packages live on disk.

Metadata and version archives stay in your data directory. No database to provision. Stop the server and back up that directory plus your config.

03 / Browsing

A web UI comes with it.

Search packages, inspect versions and npm tags, and find install snippets. The HTML, CSS, and JavaScript are embedded in the binary.

04 / Access

Open reads. Or keep them private.

Choose with private = true or false. Each user has their own token. Publishing and yanking always require authentication.

Start on localhost

Build. Configure. Run.

Build with Go 1.23 or newer. After that, your server only needs the executable and its config. The commands below use a Linux or macOS shell.

  1. 1

    Build the binary

    git clone https://github.com/skorotkiewicz/registry.git
cd registry
go build -o registry ./cmd/registry

    Prefer a prebuilt binary? Tagged builds provide Linux, macOS, and Windows artifacts for amd64 and arm64 in GitHub Actions.

  2. 2

    Give yourself a token

    cp config.toml config.local.toml
chmod 600 config.local.toml
openssl rand -hex 32

    Paste the generated token into your [[users]] entry's token field in config.local.toml. The supplied config is private by default and will not start with an empty token.

  3. 3

    Start your registry

    ./registry -config config.local.toml

    Open http://localhost:8080 and enter your token to browse packages. Configure Cargo or npm below, then publish your first package. On Windows, start the downloaded binary with registry.exe -config config.local.toml.

Taking it beyond localhost?

Set public_url to your client-facing address and put the server behind an HTTPS reverse proxy. Docker and persistent-volume instructions are in the README.

Rust crates

Cargo

Add to ~/.cargo/config.toml:

[registries.selfhost]
index = "sparse+http://localhost:8080/cargo/"
credential-provider = "cargo:token"

Publish from your crate's directory:

export CARGO_REGISTRIES_SELFHOST_TOKEN="$REGISTRY_TOKEN"
cargo publish --registry selfhost

npm packages

npm

Add to your project's .npmrc:

@selfhost:registry=http://localhost:8080/npm/
//localhost:8080/npm/:_authToken=${REGISTRY_TOKEN}

Use a package name such as @selfhost/my-package:

npm publish --registry http://localhost:8080/npm/
npm install @selfhost/my-package --no-audit

Before you deploy

Small on purpose.

Is this meant for a small team?

Yes. It runs as one process with disk storage and a shared request lock. It is built for individuals and small teams, not high-throughput public hosting. All configured users have the same publishing permissions, so give tokens only to people you trust.

Can anyone install my packages?

With private = false, anyone can browse and download. With private = true, readers need a configured user's token. Both modes require a token for publishing and yanking.

Do I need Node or Go on the server?

No. Go is needed only if you build from source. The compiled executable includes the web UI. Cargo and npm are needed on the machines that publish or install packages, not on the registry server.

Does it mirror public registries?

No. It hosts packages you publish yourself. There is no upstream proxy, user registration, npm audit service, or per-package ownership system. The README lists the supported behavior and limits.
